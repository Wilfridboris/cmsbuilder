`src/lib/gemini/client.ts:43` sets `GEMINI_MODEL = "gemini-3.8-flash"` (spec/architecture pin: `gemini-2.0-flash`, epic-1-context.md "LLM pipeline"), introduced by `a319ffe fix(1.4): use live Gemini model`. **Live re-verification by the parent (read-only `models.get` against Google's API with the project key): `gemini-3.8-flash` → HTTP 200 (valid, usable), so the core generation path works — the catastrophic "always falls back" scenario is disproven.** Two residual problems: (a) **spec divergence** — the as-built model is not the declared one; (b) the code comment (`:41-42`) claims `gemini-2.0-flash` "was retired… returns 404" but that model **also returns HTTP 200** in the same check, so the stated justification is false/outdated. ### Diff-scope lens findings (adversarial / edge-case / verification-gap)

> Ran via a delegated sub-agent over the committed range instead of the `bmad-review` skill (which reviews the working tree; the epic is fully committed and the tree is clean). Narrowing recorded. The two highest-value NEW items were re-verified by the parent against primary source.

- **F7 (MED) — Blocked-keyword validator false-rejects legitimate labels → silent fallback. [re-verified]** `containsBlockedKeyword` (`validator.ts:77-80`) is a pure `.includes()` substring test, applied to the human-facing, un-normalized `label` (`:134`, `:170`). Common trade labels containing a keyword as a substring — "Deleted?", "Grants", "Completed Deletions", "Drop-off time" (DELETE/GRANT/DROP) — reject the whole schema; the route then retries once (deterministically fails again) and provisions the hard fallback, so the user silently loses their bespoke generation. Disposition: **fix now** (drop the label check, or use word-boundary matching — keys are already normalized so the injection rationale is moot for keys and inert for display labels).
- **F8 (MED) — `normalizeTableName` mangles/empties non-ASCII keys, hitting the French path the epic commits to. [re-verified]** `utils.ts:22` `.replace(/[^a-z0-9]+/g,"_")` after lowercasing: `numéro`→`num_ro`, `coût`→`co_t`; a purely non-Latin key normalizes to empty → `field key normalized to empty` rejection → fallback. FR generation (FR35) is a headline epic feature. Disposition: **fix now** (transliterate accents before stripping; add accented-key tests).
- **F9 (MED) — Gemini timeout leaves the losing promise unhandled. [confirmed from source]** On timeout, `Promise.race` (`client.ts:73`) settles via the timer while `generatePromise` (`:61`) keeps running; nothing attaches a handler, so a later post-abort rejection surfaces as a Node `unhandledRejection`. The timeout test uses a never-resolving mock, so it never manifests. Disposition: **fix now** (attach `.catch(()=>{})` to the SDK promise).
- **F10 (MED) — `mutate` accepts `NaN`/non-integer `expectedVersion` → opaque 500.** `requireVersioned` (`mutate.ts:227`) only checks `typeof === "number"`, so `NaN`/`1.5`/`-1` pass and `.eq("version", NaN)` reaches Postgres as a 500 instead of a clean 400. Disposition: **defer** (integer/finite guard + test).
- **F11 (MED) — `overrides.ts` has no `canHideField` backstop and accepts empty-label renames.** `hideField` (`overrides.ts:94-112`) can hide the last visible field → column-less table / empty `<dl>` (`RecordDetail.tsx:82`); `renameTable/renameField` (`:38-71`) accept `""`/whitespace labels. `canHideTable` guards the table case but there is no field analogue. Disposition: **defer** (add guard + trim + tests).
- **F12 (MED) — Same-session re-generation into a reused org keeps stale/orphan rows (sibling of deferred #3).** `resolveOrg` reuses `existingOrgId` and `upsertSchema` replaces the definition, but prior `records` are never soft-deleted; colliding normalized `table_key` (both gens yield `clients`) makes idempotency dedup return the OLD rows (stale data under a fresh schema); differing keys leave orphan rows. `route-generate.test.ts` mocks `provisionGeneration`/`getSchema`/`listRecords`, so this is structurally invisible. Disposition: **defer** (bundle with deferred #3's reused-org/claim-time reset work).
- **F13 (LOW) — Seed-write drops are silently swallowed.** `provisionGeneration` (`provision.ts:138-141`) does `if (result.error) continue;` with no counter/telemetry, so a fully-empty real generation reveals as "success" indistinguishable from a legitimately sparse one. Disposition: **defer** (count + `reportError` on systematic drop).
- **F14 (LOW) — Blocked-keyword `isFallback` strip is a latent boundary trap.** `validateGeneratedSchema` returns `{ tables }` (`validator.ts:223`), dropping a top-level `isFallback`; harmless today (fallback bypasses the validator, `route.ts:226`) but a future refactor routing the fallback template through the validator would silently drop the banner flag. Disposition: **accept-as-is** (note in code).
- **Confirmed-safe (not findings):** Zod input validation (422, no LLM call) tested; session-cookie HMAC uses `timingSafeEqual` with length pre-check (`session.ts:61-66`); `filterSeedRows` cap + projection-onto-known-keys tested; soft-delete-exclusion and stale-version rejection tested (`mutate.test.ts:218-246`).
