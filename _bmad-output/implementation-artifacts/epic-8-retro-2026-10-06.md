### Diff-scope review (correctness / edge-case / verification-gap)

- **[F1 · HIGH · fix now] A purged `deleted` tombstone can be resurrected by a redelivered Stripe event — cross-story boundary defect (webhook 7.x ⨯ cascade 8.5).** `handleCheckoutCompleted` unconditionally writes `subscription_status:"active"` and clears all offboarding stamps (`src/app/api/stripe/webhook/route.ts:173-207`); `handleSubscriptionDeleted` unconditionally writes `read_only` (`:245`). Neither guards the terminal `deleted` state introduced in Story 8.5. The cascade tombstone leaves `stripe_subscription_id` intact (`src/lib/offboarding/cascade-delete.ts:128-134`), so `resolveOrgForSubscription` (`route.ts:356+`) still resolves a purged org. A redelivered `checkout.session.completed` resurrects a purged (empty) org to `active`/paid; a redelivered `customer.subscription.deleted` flips `deleted`→`read_only` (dropping the AccountClosedScreen for permanently-deleted data). The author explicitly reasoned about `read_only` terminality (`route.ts:218-220`) but did not extend that reasoning to the new `deleted` state — exactly the gap no single story review catches. **Reachability:** requires redelivery of a stale event (Stripe auto-retries ~3 days; the grace window is 30, so realistically a manual dashboard resend) against a tombstone whose subscription id still resolves → high impact, low likelihood. **Fix:** in both handlers read the current `subscription_status` and early-return (log + no-op) when already `deleted`; optionally also null `stripe_subscription_id` in the tombstone so stale events cannot resolve the org. Mirrors the existing read_only-terminal pattern the invoice handlers already use (`route.ts:313`).
- **[F2 · MEDIUM · fix now] CSV formula/injection not neutralized in the export.** `tableToCsv` (`src/lib/export/build-export.ts:82-107`) passes each raw stored cell straight to `Papa.unparse`; papaparse quotes delimiters but does not neutralize a leading `=`/`+`/`-`/`@`/tab/CR. A stored value like `=HYPERLINK("http://evil",...)` exports verbatim and executes when opened in Excel/Sheets. **Reachability:** Epic 6/14 public intake forms let untrusted external parties write records that an admin later exports and opens — a genuine cross-trust vector in this app (not merely "the owner's own data"). The 8.4 triage log considered `[object Object]` cells (rejected) but never formula injection, and `build-export.test.ts` has no injection row. JSON side is unaffected. **Fix:** prefix a cell with `'` when its stringified value starts with a formula trigger, before `Papa.unparse`; add a test row.
- **[F3 · LOW · documented, acceptable] Multi-admin partial-send re-sends to already-notified admins.** `sendStage` (`src/app/api/cron/offboarding/route.ts:175-184`) loops all admin emails; a failure on email #2 throws the whole stage, no stamp lands, and the next sweep re-sends to #1. This is the explicitly accepted "a duplicate warning beats a silently dropped one" tradeoff (`route.ts:191-192`, triaged in spec 8.5). Recorded, not an action item.

**Verified clean (what was checked):** cascade retention invariant + FK delete order (only inbound FKs to INCLUDE tables are `records`←`invoices/credit_notes.customer_record_id ON DELETE SET NULL`, so deleting `records` first cannot throw); cascade re-entrancy / partial-failure retry; cron `authorizeCron` fail-closed before any work; Day-30 boundary math (`Math.floor(.../DAY_MS) >= 30`); no non-voluntary path stamps the grace clock (voluntary-only guard `route.ts:250-252`); reactivation clears all four offboarding columns (`route.ts:184-198`); export 401→400→403 ordering before any read, RLS-scoped client (never service-role), cross-org slug 403, pagination to completeness; `isReadOnly` covers `deleted` so `assertWritable`/`assertOrgWritable` 403 a deleted org — no write path uses the non-writable gate.
