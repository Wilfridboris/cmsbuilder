## Epic summary

**Epic 14** turns the single auto-generated public intake form (epic 6) into an owner-managed, multi-form lead-capture tool. An Admin can create many public forms per dashboard, each with a title-derived editable org-scoped slug, an explicitly chosen target table, per-field public customization (visibility, public label, help text, order), business branding (operating name + logo + optional intro), and a publish toggle off by default. Abuse protection (honeypot + per-IP/per-slug rate limiting) hardens the public endpoint without dropping legitimate captures. The epic migrates the prior public page and submission handler onto a new shared `forms` entity rather than rewriting them, and preserves the hard invariant that relationship/lookup fields never reach a public form.

### Confirmed strengths (checked and clean)

- **The relation/lookup invariant holds across three independent layers.** `intakeFields` strips `type === "relation"` before any config applies (`target.ts:70-74`); `applyFieldConfig` operates only over that stripped base (`target.ts:88-108`); `updateFormFieldConfig` allowlists incoming config entries to `intakeFields(table)` keys, dropping relation/stale keys on write (`form-mutate.ts:473-513`). A crafted `field_config` cannot re-surface a relation field in render or submission.
- **Submission write is allowlisted to the server-resolved field set.** `submitToTarget` builds the write payload only by iterating `target.fields`, reading the client `values` bag key-by-key (never spread), so hidden/relation/foreign-table/extra keys are silently dropped (`submit.ts:72`). Both POST handlers re-resolve the form server-side and never trust the client for table or field set (`intake/[slug]/route.ts:55`, `intake/[slug]/[formSlug]/route.ts:53`). Write runs through the guarded `mutate` under `INTAKE_ACTOR_ID` scoped to the resolved org, passing the already-resolved schema (`submit.ts:139-147`).
- **Unavailable state is uniformly data-free.** `resolvePublicFormTarget` collapses every unavailable cause — unknown org/form, unpublished, null/stale `target_table_key`, hidden/deleted table, zero eligible fields, any thrown provider error — to a single `null` with no org-missing-vs-unpublished distinction that could leak existence; `force-dynamic` + Node runtime prevent cross-org caching (`forms-public.ts:106-224`).
- **Admin-only management enforced server-side via the shared resolver.** Every mutating form route composes `requireUser` → `resolveWritableAdminIdentity` before any DB/body work (`api/forms/route.ts:78,83`; `api/forms/[formId]/route.ts:76,81,203`); the nav link is gated on `role === 'admin'` in a server component (`DashboardNav.tsx`). RLS `forms_tenant_isolation` is the hard backstop (all writes use the RLS-scoped client, never the service-role key).
- **Logo proxy preserves the private-bucket posture.** `GET /api/forms/logo/[slug]` published-gates (404 if the org has no published form), streams bytes via the admin client (no public bucket, no signed URL), sets a short cache header, and returns bare bodyless 404s on every error path (`api/forms/logo/[slug]/route.ts`, `storage/logo.ts`).
- **Slug uniqueness is defended in depth.** `-N` suffixing scoped per org (`form-slug.ts:43-68`), DB `UNIQUE (organization_id, slug)` backstop (`20261003120000_forms.sql:51`), 23505 retry bounded at 25 (`form-mutate.ts:89-110`), slug edit rejected once published (`slugLocked`, `form-mutate.ts:206`). Publish gated on a valid target via `evaluateFormPublishability`, the same predicate the public resolver uses.
- **Honeypot + limiter never drop a legitimate capture.** Honeypot `website` is a top-level body field (no collision with a real field), silently returns the normal 200 envelope with no write/email/Sentry (`submit.ts:64`); the field is `sr-only`+`aria-hidden`+`tabIndex=-1` (`IntakeForm.tsx:282-293`). The limiter fails open on any non-429 error so machinery failure never drops capture (`rate-limit.ts:200-206`).
- **Two multi-epic recurring lessons were finally heeded.** (a) **Route-auth duplication** (a 5-epic recurrence): both new mutating routes compose the shared `resolveWritableAdminIdentity` and cite the invoices auth chain — no inline/redefined auth (`api/forms/route.ts:78`, `api/forms/[formId]/route.ts:76,203`). (b) **Public-path drift** (flagged by the 14.1 retro): the legacy bare-org route and the keyed route share ONE `resolvePublicFormTarget` + `submitToTarget` code path rather than two that can drift (`submit.ts:20-24`).
- **Conventions clean:** all server data modules carry `import "server-only"`; the client fetch layer (`forms-client.ts`) imports only `type` from server modules (erased at compile, no bundle leak); `Forms` i18n namespace has full EN/FR parity (80 keys each); **no em-dash in any added user-facing string** (the em-dashes grep surfaced are all in JSDoc/code comments).

### Abuse-protection: best-effort by design (code lens)

The 14.7 abuse protection is candidly documented as best-effort defense-in-depth with the honeypot as the primary defense; these three are recorded so the retro distinguishes *throttle intent* from *throttle guarantee*, not as defects in the as-built.

- **F1 — Per-IP limit is bypassable via `X-Forwarded-For` spoofing (Low, defer).** `getClientIp` trusts the first hop of client-controlled `X-Forwarded-For` (`rate-limit.ts:140-153`); a bot rotating that header gets a fresh per-IP bucket every request. The per-slug bucket still caps total per-form throughput and the honeypot is primary. On Vercel a platform-provided trusted client-IP header (`x-vercel-forwarded-for`) is available and would make the per-IP cap meaningful — a no-infra-change read. Disposition: defer (propose a trusted-IP-source hardening action).
- **F2 — Per-slug bucket can be weaponized to deny a popular form (Low, accept/record).** The per-slug bucket is keyed on the attacker-known public slug; an XFF-spoofing flood (F1) can drain it (60/60s) and 429 *legitimate* visitors of that specific form — the inverse of the "never block a legitimate submission" requirement. Inherent to a shared per-slug bucket; mitigated only by a real per-IP identity (F1). Disposition: accept/record.
- **F3 — Limiter state is per-instance in-memory (Low, accept/record).** Module-level `Map` (`rate-limit.ts:35`); on serverless each warm instance has its own buckets and a cold start resets them, so the effective limit is `N_instances × capacity`. No correctness bug (fails open, bounded memory), but not a hard guarantee. Disposition: accept (explicitly chosen; honeypot is primary).
